## Objective

## Help design principle

> Help should explain non-obvious concepts, important safety behavior, and low-discoverability interactions. It should not become a complete release-history list or duplicate obvious UI behavior.

Help追加を判断するときは、次を区別する。

```text
A. genuine Help gap
B. UI discoverability issue
C. product behavior issue
D. outdated Help
E. no additional Help needed
```

明らかに壊れたUIをHelpで補償しない。簡潔なHelpで十分な場合に不要なUI再設計を行わない。

## Agreed first-increment scope

### A. Snapshot / Semantic Diff / external-AI handoff

Helpで次のconceptual modelを説明する。

- Snapshotは、現在DB内の確定済みTask状態を現在DBへ保存する。
- 保存できるSnapshotは最大5件である。
- 2件のSnapshotを比較し、保存時刻によりBefore / Afterを決定する。
- Semantic Diffはraw text diffではなく、Taskの追加・削除・状態・階層・日程等のmeaningful Task-level changesを表す。
- `AIに渡す内容` と `差分JSON` は編集可能なpresentation / copy bufferである。
- `AI分析用ファイルを保存` は、canonical analysis instructionとASANYAが生成したcomplete Semantic Diffを出力する。
- exportのauthoritative Semantic Diff sourceには、textarea上の任意user editを使用しない。

Helpはoverall conceptを説明し、既存button tooltipやdialogを逐語的に重複させない。

### B. External update / conflict protection

外部更新warningの意味とsafety modelを説明する。

- external update detectionは、current stateの読込後にbacking DB fileが変更されたことを意味する。
- ASANYAが別userの現在のtypingを検知しているという意味ではない。
- 現在表示中のstateは、外部更新後のfileより古い可能性がある。
- ASANYAは変更を自動mergeしない。
- 外部更新検知だけではautomatic reloadしない。
- userは一時的に現在表示を見続けることができる。
- destructive reload前にunsaved / active local editsを保護する。
- confirmation後のrefreshは現在のlocal workを破棄する場合がある。

既存のinline warningとconfirmation dialogは、その場のoperational decisionを引き続き担う。Helpはbroader conceptual explanationを提供する。

### C. Project status `メモ`

Project Helpで、`メモ`がProject hierarchy内のnon-active reference itemであることを説明する。

現在のformal behaviorに従い、少なくとも次のactive-work semanticsから除外されることを反映する。

- ToDo display
- open / unfinished KPI
- overdue treatment
- dependency processing
- recurrence processing

Memo nodeがchildを持てる現在behaviorを保持し、説明する。現行implementation／formal testsを超える意味を創作しない。

### D. Recurring checklist roll-forward

既存のDueとrecurrence scheduleの違い、およびcatch-up説明は保持し、置き換えない。そのうえで次を追加する。

- ordinary caseでは、完全に独立した新規Taskを毎回作るのではなく、同じrecurring Task recordを次回へroll forwardする。
- recurring checklist descendantsを次cycle向けに準備する。
- completion stateとactual datesを現在のformal behaviorに従ってresetする。
- Dueを持つdescendant Taskは、対応するrecurrence shiftだけ移動する。
- 現在実装されているdependency restrictionsを保持する。

「常に新しいTaskが作成される」と誤解させる表現を使用しない。

### E. Project hierarchy collapse / expand

既にToDo Helpへ記載されているhierarchy collapse / expandと同期し、Project Helpへ簡潔な説明を追加する。詳細なhierarchy manualへ拡張しない。

### F. Shortcut Guide synchronization

current formally supported guidanceを実装およびformal testsで再確認し、Help / Shortcut Guideを同期する。最低限、次を対象とする。

- Undo: `Ctrl+Z`
- Redo: `Ctrl+Y` / `Ctrl+Shift+Z`
- Task navigation: `ArrowUp` / `ArrowDown`

`Alt+M` / `Alt+I` はcompatibility behaviorとして残っていても、current formal guideが意図的に除外している場合はrecommended shortcutとして自動復活させない。

## Draft wording — investigation evidence only

以下はHelp Gap Auditで示された方向確認用draftであり、approved canonical wordingではない。Developmentではimplementation／formal testsと照合してexact wordingを確定する。

### Snapshot / comparison

> スナップショットは、確定済みの現在のTask状態を現在DB内に最大5件保存します。2件を比較すると、保存時刻の古い方をBefore、新しい方をAfterとして、Taskの追加・削除・状態・階層・日程などの意味上の変更を生成します。

### AI handoff

> 表示中のAI内容と差分JSONは編集してコピーできます。『AI分析用ファイルを保存』は、画面上の編集内容ではなく、ASANYAが生成した完全なSemantic Diffと分析指示をMarkdownで保存します。

### External update

> 外部更新の検知は、DB fileが前回読込時から変更されたことを示します。他の人が現在編集中という意味ではなく、変更の自動mergeも行いません。未保存内容がある場合はautosaveを停止し、最新状態への更新前に破棄確認を行います。

### Memo

> メモはProject階層に参照情報を残すためのnon-active itemです。ToDo、未終了件数、overdue、依存関係、繰返しの対象にはなりません。

### Recurring checklist

> 繰返しTaskを終了すると、同じTaskとそのchecklistを次回用に進めます。配下の終了状態と実績日は戻り、日付付きの配下Taskは次回までの差分に合わせて移動します。
