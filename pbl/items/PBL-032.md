# PBL-032 — 同時編集競合の検知・上書き防止

- Type: Feature / Architecture
- Status: Validated RC
- Priority: Low
- Released: —
- Schema impact: No
- Migrated: 2026-09-12
- Last verified: 2026-10-07

## Objective

既存の外部更新検知を、ヘッダーが画面外でも見落とさないよう現在viewportへ常時表示し、安全な再読込操作へ直接到達できるようにする。

## Current scope and decisions

- 信頼できるトリガーは「現在DBへの外部更新をASANYAが検知済み」であり、他ユーザーが編集中だとは表示しない。
- 外部更新中は、ヘッダーが画面外でも見える固定・非modal・永続通知を表示する。
- 通知には `最新状態に更新` の直接操作を置き、既存の現在DB再読込経路を共有する。
- 検知だけでは自動再読込しない。ユーザーは現在表示を一時的に閲覧・スクロールできる。
- 未保存変更、draft、未確定editorがある場合は、再読込前に破棄確認を必須とする。取消時は現在内容と外部更新状態を保持する。
- 既存ヘッダーの外部更新表示と再読込操作も同じ安全経路を利用する。
- 外部更新解消後は固定通知を消す。
- PBL-046の期限曜日表示と104px期限列を維持する。
- Schema 3.2、persistence形式、外部更新検知方式は変更しない。
- server collaboration、presence、locking、outbox、backend同期、persistence全体の再設計は対象外。PBL-043～045は開始しない。

## Acceptance criteria

- 外部更新検知時だけ固定通知が表示され、通常時は表示されない。
- ページヘッダーを画面外へスクロールしても通知と更新操作を利用できる。
- 通知は自動消滅せず、外部更新状態の解消まで表示される。
- 検知だけでは画面dataを自動置換しない。
- 通知からの更新が既存の現在DB再読込経路を利用し、成功後に外部更新状態と通知を解消する。
- 未保存または編集中の内容を確認なしに破棄しない。
- 既存ヘッダー表示・自動保存停止・保存前freshness確認を維持する。
- PBL-046が退行しない。

## Relationships

PBL-015およびPBL-043～045と関連するが、本Developmentでは既存File System Access外部更新検知のUXと安全な再読込入口だけを扱う。lock lifecycle、presence、item単位競合解決、cloud実装は将来範囲として残る。
